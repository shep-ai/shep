## Findings

- `AgentQuestion` (spec 093) already models urgency, answerer, status, `defaultAnswer` and
  `expiresAt`; the deferred registry already polls the DB so answers from another process
  settle an awaiter. The unified pipeline is gated on `featureFlags.collaboration`.
- Both interactive executors (`claude-code-interactive-executor.service.ts`,
  `cursor-interactive-executor.service.ts`) call `options.agentQuestionBridge.ask()` first and
  fall back to `onUserQuestion` when it returns null. `session-bootstrapper.ts` never passes a
  bridge, so the bridge is dead code in production.
- `FeatureAgentGateQuestionPublisher` writes `JSON.stringify({event:'waiting_approval', ...})`
  as the prompt; the supervisor router uses that JSON as its gate discriminator.
- The inbox page lists questions per Application id. Gate questions for a repository without an
  Application are scoped by repository path and never appear — the page must also list the
  scopes that questions were actually written under.
- `ChatTab` renders `InteractionBubble` in `afterMessages`, contrary to
  `features/chat/CLAUDE.md` rule 1.
- Headless prompts (`fast-implement.prompt.ts`, `prototype-generate.prompt.ts`) forbid asking.
- Only executors that honour `mcpConfigPath` (Claude Code today) can be given the MCP tool.

## T3 Code reference behaviour (adopted)

- Option rows: bold label, muted description, `1`–`9` key hint that becomes a check when
  selected; number keys ignored while focus is in an editable field.
- Single-select: optimistic check, auto-advance after 200 ms; multi-select toggles in place.
- Custom text outranks the selection; clicking an option moves typed text back into the
  composer draft (`carryDisplacedCustomAnswerIntoPrompt`).
- Multi-question requests page with `n/N`, Previous / Next / Submit; Enter advances.
- `not_resumable` requests are shown but cannot be answered.

## Security Considerations

- `ask_decision` input is model-supplied: lengths are bounded, option ids are generated by Shep
  (not taken from the model), and nothing reaches a shell.
- The MCP server process inherits the worker's scope only through env vars it sets itself; a
  tool call cannot address another feature's questions.
- Option `preview` is rendered as text in a `<pre>`, never as HTML.

## Performance Implications

- Two JSON columns, parsed in the mapper; inbox queries are unchanged.
- The deferred registry's 2 s DB poll already exists; the MCP server reuses it (one awaiter per
  open agent-asked decision).
