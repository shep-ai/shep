---------------------------------------------

$ lsof -a -p 56801 -d cwd

Two facts follow:

  (a) It executes evidence-output-parser.ts from /Users/ariel/Code/shep — the
      MAIN checkout, on branch main (b8f7a72). The fix lives on this feature
      branch and has not merged, so that copy still reads:

      $ grep -n "baseDir\|resolveEvidencePath" \
          /Users/ariel/Code/shep/packages/core/src/.../evidence-output-parser.ts
      (no matches)

      i.e. still `await stat(e.relativePath)` with no base directory.

  (b) Its process.cwd() is /Users/ariel/Code/shep, NOT the worktree the
      evidence was written and committed to.

So `stat('specs/108-dev-server-auto-start/evidence/app-run-plan-collapsed.png')`
resolves to /Users/ariel/Code/shep/specs/108-.../app-run-plan-collapsed.png,
which does not exist on main.

REPRODUCTION (run from the worker's cwd):

$ cd /Users/ariel/Code/shep && node -e "const{stat}=require('fs/promises'); \
   stat('specs/108-dev-server-auto-start/evidence/app-run-plan-collapsed.png') \
   .then(()=>console.log('FOUND')) \
   .catch(e=>console.log('ENOENT ->',e.code,'| cwd was',process.cwd()))"
ENOENT -> ENOENT | cwd was /Users/ariel/Code/shep

That is the exact message the validator reported, for the exact reason. It is
a path-resolution fault, not missing evidence.

Note the worker is long-lived and loaded the module at startup, so even
updating the main checkout on disk would not change the running process's
behaviour. The fix cannot take effect until this branch merges and a new
worker starts.

5. FOLLOW-UP ALREADY ON THIS BRANCH
-----------------------------------
Commit fdfb596 makes validateFileExistence take the base directory as an
explicit parameter and threads options.cwd through validateEvidence from
evidence.node.ts, covered by a real-filesystem test that points process.cwd()
deliberately away from the fixture. Once merged, a freshly started worker
resolves committed evidence correctly and this mirror becomes unnecessary.

here; it is worth its own spec.
