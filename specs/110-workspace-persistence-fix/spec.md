## Problem Statement

When a user creates one or more new workspaces in the Control Center's
workspace switcher and then closes and reopens the browser, the created
workspaces are gone — only the default workspace remains. The bug is in
`useWorkspaces()`: on mount, a hydration effect (`setState(loadState())`)
and a persist effect (`saveState(state)`, deps `[state]`) both run. The
persist effect can fire with the pre-hydration `INITIAL_STATE` value and
overwrite `localStorage` before hydration has propagated into state.
Separately, `loadState()` returns the literal `INITIAL_STATE` object by
reference from three of its four branches, so `setState(loadState())` is
sometimes a referential no-op that never re-triggers the persist effect
to correct the clobbered value.

## Success Criteria

- [ ] Creating one or more workspaces in the Control Center, then closing

- [ ] The persist effect in `useWorkspaces` never writes to `localStorage`

- [ ] `loadState()` returns a freshly constructed object on every code

- [ ] New unit tests cover: (a) the persist-effect-must-wait-for-hydration

      and (c) multiple workspaces surviving a simulated remount of the hook.
- [ ] No regression to existing Control Center / workspace UI behavior —
      all existing Control Center tests remain green.
